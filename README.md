# claude-starter

Claude Code **오케스트레이터 강제 모드** 스타터 템플릿.

* **메인 세션 역할** — 직접 코드 수정은 하지 않음, 작업 계획 및 분배·검토만 진행.
* **실제 작업** — implementer·explorer·planner·reviewer 등 서브에이전트가 수행.

아이디어 → 기획 → 기술설계 → 병렬 구현 → 검증 → 반영까지의 기본 작업 흐름과,
세션이 바뀌어도 이어서 작업할 수 있도록 STATE/MAP/GOTCHAS 기록 체계가 기본 구성되어 있다.

* **기본 언어** — 한국어
* **기술 스택** — 프로젝트별 `/architect` 단계에서 결정

## 목적

| 목적      | 장치                                                                 |
| ------- | ------------------------------------------------------------------ |
| 역할 분리   | 메인 세션은 계획·분배·검토만 진행. 실제 코드 작성 및 수정은 서브에이전트가 담당                     |
| 컨텍스트 보호 | 큰 파일이나 긴 실행 결과는 그대로 불러오지 않고 필요한 내용만 요약. 서브에이전트 작업 종료 후 해당 컨텍스트도 종료 |
| 병렬 작업   | 독립 작업은 여러 에이전트가 동시에 진행. 충돌 가능성이 있는 작업은 worktree로 분리                |
| 기록 유지   | 진행 상태는 STATE.md, 프로젝트 구조는 MAP.md, 반복하면 안 되는 문제는 GOTCHAS.md에 기록     |

**기본 규칙** — 별도 지시가 없을 때 적용.

사용자가 다른 방식을 명확하게 요청하면 사용자 지시를 우선 적용한다.

* **이번 실행에서만 직접 수정 허용** — `claude --agent general-purpose`
* **오케스트레이터 모드 영구 해제** — `settings.json`에서 `"agent"` 설정 삭제

## 세션 시작 시 로드 흐름

```text
claude 실행
 ├─ 1. CLAUDE.md            기본 운영 규칙 자동 로드
 │     └─ 관련 문서 3종 함께 로드
 │        ├─ docs/STATE.md          지난 작업 진행 상태
 │        ├─ docs/GOTCHAS.md        기존 문제 및 주의사항
 │        └─ docs/PROJECT-RULES.md  프로젝트 전용 규칙
 └─ 2. SessionStart 훅 → 현재 프로젝트 상태 자동 점검
       TEMPLATE-REPO / PROJECT-REPO SETUP-PENDING / ASK-MODE
       RTK-MISSING / MAP-STALE / KB-OVER-LIMIT / ARCHITECT-PENDING / ORCA-ENV 등
```

* **세션 시작** — 프로젝트 상태와 이전 작업 내용을 자동 확인.
* **문제 감지** — 필요한 도구 설치, MAP 갱신, 초기 설정 등 선행 작업부터 처리.
* **작업 재개** — 새 세션에서도 이전 내용의 재설명 없이 이어서 진행.

## 표준 작업 흐름

```text
아이디어
 → /kickoff    아이디어 구체화 → 기획 → 목표 정리 → 목업 제작 → 사용자 승인
 → /architect  프로젝트 조사 → 기술·스택·구현 방식 결정 → 기술계획 승인 → 개발 준비 → 작업 생성
 → 구현        implementer 병렬 작업
 → 검증        reviewer pass/fail 판정
 → /land       검증된 작업 반영 → 정리 → push
 → /handoff    현재 상태와 주요 내용 기록 → 다음 세션으로 전달
```

1. `/kickoff` 이후 목업 제작 및 사용자 승인 단계

   * 아이디어 구체화
   * 필요한 기능 및 목표 정리
   * 목업 제작
   * 사용자 확인 및 승인
   * 완료 후 `/architect` 진행 제안

2. `/architect` 기술 설계 단계

   * 기존 프로젝트 및 개발 환경 확인
   * 사용할 기술·스택 결정
   * 데이터 구조 및 구현 방식 결정
   * 여러 구현 방법이 있으면 비교 후 적합한 방식 제안
   * 기술 계획 승인 후 실제 개발 준비

3. 구현 단계

   * 전체 작업을 작은 단위로 분리
   * 서로 독립적인 작업은 여러 implementer가 병렬 진행
   * 작업 충돌 가능성이 있으면 worktree로 분리

4. 검증 단계

   * reviewer가 구현 결과 확인
   * 정상 : `pass`
   * 수정 필요 : `fail`
   * 결과 저장 : `.claude/review/last-verdict.md`

5. `/land` 반영 단계

   * `pass` 받은 작업만 최종 반영
   * worktree 정리
   * 연결된 GitHub 이슈 종료
   * 원격 저장소 push

6. `/handoff` 세션 정리 단계

   * 현재 진행 상태 저장
   * 다음 작업 기록
   * 새 세션에서도 바로 이어서 작업할 수 있도록 정리

**검증 기준** — 세션의 이전 대화가 아니라 **판정 파일**을 기준으로 처리.

다음 조건을 모두 만족해야 머지·이슈 종료·push 가능.

* `.claude/review/last-verdict.md` 존재
* 판정 결과 `pass`
* 검증받은 코드와 현재 작업 코드가 동일

**GitHub 미사용 프로젝트** — GitHub 이슈 대신 `docs/STATE.md`의 "다음 할 일"을 작업 목록으로 사용.

`/handoff` 실행 순서 :

```text
/handoff
 1. 중요한 지식 정리
    → 이번 작업에서 발견한 주의사항 선별
    → 필요한 내용 GOTCHAS.md 기록
    → MAP.md 오래된 내용 정리

 2. 현재 상태 저장
    → docs/STATE.md 갱신
    → 프로젝트 / 현재 상태 / 다음 할 일 / 특이사항 기록

 3. 마무리
    → 변경사항 커밋
    → 미push 커밋 push
    → /clear 후 다음 작업 진행
```

**`/clear` 또는 새 세션 시작** — `STATE.md` 자동 로드 후 바로 다음 작업 진행 가능.

## 주요 문서 역할

| 파일                      | 역할                         | 성격                                    |
| ----------------------- | -------------------------- | ------------------------------------- |
| `docs/STATE.md`         | 현재 진행 상태와 다음 작업 기록         | `/handoff`마다 최신 내용으로 갱신, 최대 150줄      |
| `docs/MAP.md`           | 프로젝트 구조·주요 파일·명령어·개발 방식 기록 | 프로젝트 구조 참고용, 최대 120줄                  |
| `docs/GOTCHAS.md`       | 기존 문제와 재발 방지 방법 기록         | 반복 실수 방지용, 최대 100줄                    |
| `docs/PROJECT-RULES.md` | 프로젝트 전용 규칙 기록              | 템플릿 업데이트 시에도 유지                       |
| `docs/MACHINE.md`       | 해당 컴퓨터에서만 사용하는 경로·명령 기록    | Git 미추적, `MACHINE.md.example` 복사 후 사용 |

## 주요 명령

* `/kickoff` — 아이디어 구체화 → 기능·목표 정리 → 목업 제작 및 승인
* `/architect` — 기술·스택·데이터 구조·구현 방식 결정
* `/import` — 기존 별개 레포를 코드 변경 없이 템플릿 체계로 흡수 (세팅·규칙만 이관)
* `/land` — 검증 완료된 작업 최종 반영
* `/handoff` — 현재 상태 저장 및 다음 세션 준비
* `/perf` — 세션 병목 리포트 (구간별 소요 시간 분석)
* `/template-update` — 기존 프로젝트에 최신 템플릿 기능 반영
* `/webapp-testing` — 브라우저로 UI 실제 동작 검증
* `/cheatsheet` — 자주 사용하는 명령 확인
