# 0.0.1 — 2026-08-19

버전 체계를 도입하기 전까지 쌓인 상태를 첫 릴리즈(한 번에 묶어 내놓는 버전 하나)로 묶고, 이번에 사용 안내 문서와 변경 기록(릴리즈 노트) 방식을 손봤다.

제목의 `(기준선)`은 이번에 바꾼 게 아니라 원래부터 있던 기능을 처음 기록해 두는 항목이라는 표시다.

## [RN-0001] 사용 안내 문서를 항목별로 갈라 정리

- 기존: 사용 안내 문서에 서로 다른 이야기가 한 줄에 뭉쳐 있었고, 제목이 말 거는 투라 제각각이었다.
- 페인포인트: 필요한 내용을 찾으려면 줄 전체를 다 읽어야 했고, 훑어봐서는 어느 대목인지 짚기 어려웠다.
- 개선: 한 줄에 한 가지만 담도록 항목을 나누고, 제목을 짧은 명사형으로 통일해 훑기만 해도 찾을 수 있게 했다.

## [RN-0002] 시작 안내 화면에 자주 쓰는 기능 노출

- 기존: 프로그램을 켤 때 뜨는 시작 안내 화면에는 쓸 수 있는 기능 중 일부만 적혀 있었다.
- 페인포인트: 거기 적혀 있지 않은 기능은 있는 줄도 몰라서 쓰지 못했다.
- 개선: 속도 점검(`/perf`)처럼 자주 쓰는 기능을 시작 안내 화면에 함께 띄워 켜자마자 눈에 들어오게 했다.

## [RN-0003] 변경 기록 체계 신설

- 기존: 무엇이 언제 바뀌었는지가 개발 이력에만 남아 있었다.
- 페인포인트: 바뀐 내용을 알려면 개발 기록을 직접 뒤져야 해서 개발자가 아니면 사실상 확인할 수 없었다.
- 개선: 버전마다 "기존·페인포인트·개선" 세 줄로 정리한 기록을 남기고, 항목마다 고유 번호를 붙여 나중에 짚어 말할 수 있게 했다.

## [RN-0004] (기준선) 계획·작업·검토를 나눠 맡는 진행 방식

- 기존: 하나의 대화가 계획부터 작업, 점검까지 전부 떠맡았다.
- 페인포인트: 일이 커질수록 앞에서 정한 내용을 놓치고, 확인 없이 이것저것 손대는 일이 생겼다.
- 개선: 중심 대화는 계획을 세우고 나눠주고 결과를 검토만 하며, 실제 작업은 별도 담당이 맡도록 기본값을 정해뒀다.

## [RN-0005] (기준선) 진행 상황과 겪은 문제를 이어가는 기억 체계

- 기존: 대화를 새로 시작하면 앞선 맥락이 사라졌다.
- 페인포인트: 매번 상황을 처음부터 다시 설명해야 했고, 한 번 겪은 문제를 똑같이 또 겪었다.
- 개선: 진행 상황·한 번 데인 문제·구조 요약을 정해진 자리에 남겨, 새 대화에서도 이어서 볼 수 있게 했다.

## [RN-0006] (기준선) 일이 어긋나지 않게 막아두는 기본 안전장치

- 기존: 되돌리기 어려운 작업도 다른 작업과 똑같이 그냥 실행됐다.
- 페인포인트: 비밀번호 성격의 값이 실수로 기록에 남거나, 남의 작업을 덮어쓰는 사고가 날 여지가 있었다.
- 개선: 위험한 몇 가지는 실행 전에 반드시 확인을 받거나 아예 막히도록 기본 설정에 넣어뒀다.

## [RN-0007] 기능 목록을 안내 화면·조회 카드·안내 문서에서 하나로 맞춤

- 기존: 쓸 수 있는 기능 목록이 시작 안내 화면, 명령 조회 카드, 사용 안내 문서에 따로 적혀 있어 서로 달랐다.
- 페인포인트: 어디를 보느냐에 따라 없는 기능처럼 보여서, 쓸 수 있는 기능을 놓치거나 설명이 제각각이었다.
- 개선: 세 곳의 목록과 설명 문구를 같은 내용으로 맞춰, 어디를 보든 같은 기능 목록과 같은 설명이 나오게 했다.

## 파생 프로젝트 영향

없음 — 파생 프로젝트(이 템플릿을 복사해 만든 다른 프로젝트)는 첫 기준선 릴리즈라 따로 손볼 것이 없다. 다음 버전부터는 이 자리에 업데이트 후 사용자가 해야 할 일을 적는다.
