# 0.1.0 — 2026-08-19

여러 작업이 동시에 돌아갈 때 각각이 지금 어디까지 왔는지 화면 아래에 계속 보여주는 진행 현황판을 새로 넣었다. 켜려면 설정 파일을 한 번 손봐야 해서 자리 번호를 0.1로 올렸다.

## [RN-0010] 동시에 돌아가는 작업들의 진행 현황판 신설

- 기존: 여러 작업을 나눠 맡기면 각각이 조사 중인지 작업 중인지 끝났는지 알 길이 없어 다 끝날 때까지 기다리거나 하나씩 물어봐야 했다.
- 페인포인트: 멈춘 작업과 오래 걸리는 작업이 겉으로 똑같아 보여서, 이미 죽은 작업을 몇십 분씩 기다리는 일이 반복됐다.
- 개선: 화면 아래 상태 줄에 작업별로 단계·경과 시간·짧은 메모가 색과 함께 계속 뜬다. 최대 8줄까지 보이고 넘치면 나머지 개수를 한 줄로 요약하며, 6시간 지난 기록은 알아서 사라진다.

## [RN-0011] 각 담당이 단계가 바뀔 때마다 스스로 보고하도록 의무화

- 기존: 진행 상황을 알려면 담당에게 직접 물어보는 수밖에 없었고, 대답이 올 때까지는 아무것도 알 수 없었다.
- 페인포인트: 물어보는 것 자체가 방해라 자주 못 물었고, 그래서 진행 현황이 늘 실제보다 뒤늦게 파악됐다.
- 개선: 담당들이 조사 시작·작업 시작·검증 시작·완료·실패 다섯 시점에 자기 상태를 남기도록 규칙에 넣었다. 이 기록은 본 작업을 절대 막지 않고, 실패해도 조용히 넘어간다.

## [RN-0012] 별도 작업 공간에서 남긴 기록이 사라지던 문제 해결

- 기존: 작업을 별도 공간에 격리해 맡기면 거기서 남긴 진행 기록이 본 작업 공간에서는 보이지 않았다.
- 페인포인트: 멀쩡히 일하고 있는 작업이 현황판에서 "시작도 안 함"으로 표시돼, 상황 판단이 정반대로 뒤집혔다.
- 개선: 기록을 쓰는 쪽과 읽는 쪽 모두 항상 본 작업 공간을 기준으로 삼도록 맞췄다. 하위 폴더에서 남긴 기록도 현황판에 뜨는 것까지 실제로 확인했다.

## [RN-0013] 현황판을 켜려면 설정 파일 한 곳을 직접 고쳐야 한다

- 기존: 설정 변경은 대부분 자동으로 반영돼 사용자가 따로 할 일이 없었다.
- 페인포인트: 이번에 필요한 설정 파일은 안전장치 때문에 프로그램이 스스로 고칠 수 없어, 손대지 않으면 현황판이 아예 뜨지 않는다.
- 개선: 필요한 설정 두 줄(현황판 갱신 주기, 담당 시작 시점 알림)을 사용자가 직접 넣도록 안내하고, 넣은 뒤 프로그램을 한 번 껐다 켜면 적용되도록 정리했다.

## 파생 프로젝트 영향

**손볼 것이 있다.** 파생 프로젝트(이 템플릿을 복사해 만든 다른 프로젝트)는 동기화 후 설정 파일에 위 두 줄을 직접 넣고 프로그램을 재시작해야 현황판이 뜬다. 넣지 않아도 기존 동작은 그대로이며, 진행 현황만 보이지 않는다.
