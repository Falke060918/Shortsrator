# Shortsrator — 솔루션 개발 명세서 (v1)

> 목적: 테마 기반 유튜브 숏츠 자동화 플랫폼 "Shortsrator"의 구현 명세.
> 함께 제공되는 문서: `02_제작방법론_소스정리.md` (파이프라인 설계 원리 — 반드시 준수), `03_테마명세_신비한건축사전.md` (첫 테스트 테마 프리셋).

---

## 1. 제품 개요

**한 줄 정의**: 유튜브 채널을 연동하고, 채널마다 고정된 "테마(프롬프트·규칙 세트)"에 따라 숏츠를 반자동으로 생산·업로드하는 로컬 솔루션. 사람은 중간 컨펌 게이트에서만 개입한다.

**두 개의 모드**

| 모드 | 역할 |
|---|---|
| **Theme Lab (테마 연구)** | 새 테마를 솔루션 안에서 AI 주도로 연구·실험·개선하여 "확정(FIXED)"까지 끌어올리는 모드 |
| **Production (운영)** | 확정된 테마-채널 쌍에 대해 파이프라인을 반복 실행: 생성 → 컨펌 → 조립 → 업로드 |

**설계 대원칙** (근거: 02 문서)
1. Text-to-Video가 아닌 **Image-to-Video 중심** 파이프라인.
2. **TTS 우선**: 오디오 실측 길이가 모든 컷 길이를 결정한다.
3. **완전 자동화 금지**: 컨펌 게이트(시나리오/첫 프레임/클립)는 설계상 스킵 불가. 목표는 편당 작업시간 60분.
4. **벤더 락 금지**: 모든 생성 모델은 어댑터 뒤에 둔다. 모델 교체가 설정 변경만으로 가능해야 한다.
5. **측정 없는 확장 금지**: 첫 프레임 승인률·클립 채택률이 안정되기 전엔 편수 확대를 막는다.

## 2. 도메인 모델

```
Channel 1 ──── 1 Theme (FIXED 상태일 때 바인딩)
Theme   1 ──── N ThemeVersion (규칙 변경마다 버전 증가)
Theme   1 ──── N Episode (편)
Episode 1 ──── N Shot
Episode 1 ──── N GateDecision (컨펌 기록)
Shot    1 ──── N GeneratedAsset (이미지/클립 후보들)
Topic(주제) 1 ─ N MasterAsset (기준 이미지 4장)
```

### 2-1. Theme (테마)
테마 = 버전 관리되는 규칙 세트. 상태: `DRAFT → TESTING → FIXED → ARCHIVED`.

ThemeVersion에 포함되는 필드:
- `style_string`: 모든 이미지 프롬프트 끝에 붙는 고정 스타일 문자열
- `master_asset_schema`: 주제당 만들 기준 이미지 목록 (예: 외경/내부/단면/컷어웨이)
- `camera_grammar`: 카메라 7종 각각의 사용 여부·선호도·용도 매핑
- `script_rules`: 대본 톤, 훅 패턴, 길이(초), 초당 음절 수, 구조(훅→정보→마무리)
- `shot_rules`: 컷 길이 리듬(초반/중반/리빌), 샷 수 범위, 생성방식 비율(I2V 70/S+E 15/T2V 10/편집 5)
- `edit_rules`: BGM 목록(2~3곡), SFX 규칙, 자막 스타일, 오버레이 규칙
- `voice_config`: TTS 벤더·보이스 ID·톤 설정
- `model_config`: 단계별 사용할 어댑터 (LLM/이미지/영상/TTS)
- `upload_template`: 제목/설명/태그 템플릿, 업로드 주기
- `changelog`: 이 버전에서 무엇을 왜 바꿨는지
- 버전별 누적 메트릭(승인률/채택률)이 연결됨 → "어느 버전이 좋았는지" 추적 가능

### 2-2. Channel
- YouTube OAuth 토큰, 채널 ID, 바인딩된 Theme ID(1:1), 업로드 히스토리.

### 2-3. Episode (편)
- 상태 머신: `TOPIC → SCRIPT → SCRIPT_GATE → TTS → SHOTLIST → MASTER_ASSET → FRAME_GEN → FRAME_GATE → VIDEO_GEN → CLIP_GATE → ASSEMBLY → FINAL_GATE → UPLOAD → PUBLISHED`
- 어느 단계에서든 이전 단계로 반려 가능 (예: 프레임 게이트에서 "이미지 프롬프트가 문제" → FRAME_GEN 재실행).
- 편 종료 시 메트릭 자동 기록: 첫 프레임 승인률, 클립 채택률, 소요 시간, 생성 비용(크레딧/원).

### 2-4. Shot
- 필드: 순번, 내레이션 문장, **실측 길이(초, TTS 기준)**, 생성 방식(`I2V | START_END | T2V | EDIT_ONLY`), 카메라 무빙(7종 중 선택 + 조합), 이미지 프롬프트(= 피사체 기술 + 테마 style_string), 영상 프롬프트(motion만), 채택된 클립 구간(in/out).

## 3. Production 파이프라인 (핵심 기능)

각 단계는 잡(Job)으로 실행되며, 게이트 단계는 사용자 입력이 올 때까지 대기한다.

### STEP 1. 주제 선정
- 테마별 주제 큐(Topic Queue): LLM이 테마 규칙에 맞는 주제 후보를 생성·보충, 사용자가 큐를 관리.
- 편 시작 시 큐에서 하나 pop (또는 사용자가 직접 지정).

### STEP 2. 대본 생성
- LLM + 테마의 `script_rules` 고정 포맷 프롬프트.
- 한국어, 초당 4~5음절로 목표 길이 산출. 훅→정보→마무리 구조 강제.
- 후보 2~3개 생성.

### 🔶 GATE 1 — 시나리오 컨펌
- UI에서 대본 후보를 보여주고 사용자가 선택/수정/재생성 지시.

### STEP 3. TTS 생성 (오디오 우선)
- **문장 단위로 TTS를 생성**하여 각 문장의 실측 길이를 초 단위로 확보 (파형 분석 불필요, 문장별 파일 길이가 곧 컷 길이).
- 어댑터: ElevenLabs / Typecast. 테마의 `voice_config` 사용.

### STEP 4. 샷리스트 생성
- 규칙: **내레이션 문장 1개 = 샷 1개** (1:1 매핑).
- 각 샷에 자동 배정: 실측 길이, 생성 방식(테마 비율 규칙 반영), 카메라 무빙(문장 의미와 카메라 문법 매핑 — LLM이 테마 `camera_grammar` 기준으로 선택), 컷 리듬 검증(초반 짧게/리빌 길게).
- **카메라-내레이션 동기화 검사**: 문장이 말하는 내용과 카메라 동선이 일치하는지 LLM이 자체 검증 (예: "지하에 있다" → descending 계열이어야 함).

### STEP 5. 마스터 애셋 생성
- 주제당 테마 `master_asset_schema`에 정의된 기준 이미지 생성 (예: 4장).
- 이후 모든 첫 프레임 생성 시 레퍼런스로 재사용 (API가 지원하면 reference 입력, 아니면 프롬프트 일관성 + 지시서에 명시).

### STEP 6. 첫 프레임 이미지 생성
- 프롬프트 = `[샷별 피사체·구도 기술] + [테마 style_string 고정 부착]`.
- 샷당 2~4장 후보 생성.

### 🔶 GATE 2 — 첫 프레임 컨펌 (가장 중요한 게이트)
- UI: 샷별 후보 이미지 그리드 → 승인/반려/재생성.
- 반려율 60%가 정상임을 UI에 명시. 승인/반려 데이터가 **첫 프레임 승인률** 메트릭이 됨.
- 재생성 시 반려 사유 입력 가능 → 프롬프트 자동 수정에 반영.

### STEP 7. 영상 생성 (Image-to-Video)
- 승인된 프레임 + motion 전용 프롬프트(02 문서의 공식: CAMERA + PATH + REVEAL + ENV MOTION + CONTINUITY, 카메라 동작 1~2개·리빌 최대 3개 강제).
- 샷당 2~3회 생성. Start+End Frame 방식 샷은 두 프레임 입력.

### 🔶 GATE 3 — 클립 컨펌
- UI: 샷별 생성 클립을 재생하며 **쓸 구간(1.5~3초) in/out 마킹** 또는 폐기/재생성.
- 채택 데이터가 **클립 채택률** 메트릭이 됨.

### STEP 8. 조립 (Assembly)
- ffmpeg 기반 자동 조립: 채택 클립을 실측 컷 길이에 맞춰 연결 + TTS 오디오 트랙 + BGM(테마 로테이션) + 컷 전환 SFX + 자막 번인(스크립트 기반, 타이밍은 TTS 실측).
- 무음 0.5초 이상 검출 시 경고.
- **화살표·수치 오버레이 등 정밀 편집이 필요한 편은 "CapCut 마감 모드"**: 조립본 + 오버레이 지시서(어느 초에 어떤 화살표/수치)를 내보내고, 사용자가 완성본을 다시 넣으면 다음 단계 진행.

### 🔶 GATE 4 — 최종 컨펌
- 완성본 미리보기 + 제목/설명/태그(템플릿 자동 생성) 확인·수정.

### STEP 9. 업로드
- YouTube Data API로 바인딩된 채널에 업로드(즉시/예약). Shorts 규격(9:16, ≤60초) 검증.

### STEP 10. 기록
- 편 메트릭 저장, 비용 저장, 테마 버전에 누적.

## 4. Theme Lab (테마 연구 모드)

새 테마를 만드는 AI 주도 연구 프로세스. 전 과정이 솔루션 안에서 수행된다.

1. **입력**: 테마 컨셉(예: "역사 속 전투 탑뷰") + 레퍼런스(유튜브 링크/채널/이미지, 선택).
2. **AI 연구**: LLM이 레퍼런스와 02 방법론을 바탕으로 ThemeVersion 초안 생성 — style_string, 카메라 문법 매핑, 대본 톤, 마스터 애셋 스키마, 편집 규칙, 주제 후보 20개.
3. **파일럿 제작**: 15초 5컷 표준 파일럿(02 문서 §12 템플릿)을 Production 파이프라인 그대로 실행 (게이트 포함).
4. **측정·진단**: 승인률 < 40% → 이미지 프롬프트 개선안 자동 제안 / 채택률 < 30% → 카메라 프롬프트 단순화 자동 제안. 사용자가 승인하면 새 ThemeVersion.
5. **반복**: 파일럿 2~3회, 두 지표가 임계값 이상으로 안정되면 —
6. **확정(FIXED)**: 테마를 채널에 바인딩. 이후 Production 모드에서 반복 생산.

## 5. 운영 개선 루프 (선택 확장 — v1에 훅만, 구현은 후순위)

- FIXED 테마도 편마다 메트릭 누적 → 대시보드에서 버전별 추이 표시.
- 임계값 하락 시 개선 제안 생성 → **사용자 승인 시에만** 새 ThemeVersion 적용 (운영 중 무단 변경 금지).
- (확장) YouTube Analytics API로 조회수·시청지속률 수집 → 테마 버전·훅 유형과 상관 분석 → 주제 선정·훅 개선에 반영.

## 6. 모델 어댑터 레이어

모든 외부 생성 서비스는 공통 인터페이스 뒤에 둔다. 테마의 `model_config`가 단계별 어댑터를 지정.

```
LLMAdapter        generate(prompt, schema?) 
TTSAdapter        synthesize(text, voice) → audio + duration
ImageAdapter      generate(prompt, refs[], aspect) → images[]
VideoAdapter      i2v(image, motionPrompt, duration) → clips[]
                  startEnd(frameA, frameB, prompt) → clips[]
                  t2v(prompt) → clips[]   (B-roll 전용)
```

**v1 어댑터 대상**: LLM = Claude API / TTS = ElevenLabs(+Typecast) / 이미지 = API 가용 모델(예: Gemini 이미지, Flux 등) / 영상 = Veo(Gemini API), Runway API, Kling API.

**MANUAL 어댑터 (하이브리드 모드) — 필수**: API가 없거나 웹 전용 기능(Flow Ingredients 등)을 쓰는 단계를 위해, 모든 어댑터에 MANUAL 구현을 제공한다:
- 솔루션이 **복붙 가능한 제작 지시서**(프롬프트 + 레퍼런스 이미지 + 설정)를 화면에 출력하고,
- 사용자가 외부 툴에서 생성한 파일을 드롭 존에 넣으면 파이프라인이 이어서 진행.
- 이 방식 덕분에 **영상 API 없이도 파이프라인 전체가 v1부터 동작**한다.

## 7. 시스템 아키텍처 (권장)

- **형태**: 로컬 웹앱 (localhost). 백엔드 + 브라우저 UI.
- **권장 스택**: TypeScript / Node.js + 웹 프레임워크(Next.js 또는 Fastify+React), DB는 SQLite, 미디어 처리는 ffmpeg (자막 번인·조립·길이 측정), 잡 큐는 인프로세스(BullMQ 급 불필요, 단순 상태 머신 + 폴링으로 충분).
- **파일 워크스페이스**: `workspace/{채널}/{테마버전}/{에피소드}/` 아래 `script/ tts/ frames/ clips/ master/ final/` — 모든 산출물은 파일로 보존, DB는 메타데이터만.
- **비밀키**: API 키·OAuth 토큰은 로컬 설정 파일(.env / OS 키체인), 코드에 하드코딩 금지.

### UI 화면 목록
1. **대시보드**: 채널·테마 라인 목록, 진행 중 에피소드, 대기 중 게이트(뱃지).
2. **게이트 화면** (핵심 UX): 대본 선택 / 프레임 그리드 승인 / 클립 재생+구간 마킹 / 최종 미리보기. 키보드 단축키로 고속 선별 지원.
3. **Theme Lab**: 테마 생성 위저드, 버전 diff, 파일럿 실행, 메트릭 진단 카드.
4. **테마 상세**: 규칙 편집기, 주제 큐, 버전 히스토리+메트릭 그래프.
5. **에피소드 타임라인**: 상태 머신 시각화, 단계별 재실행.
6. **설정**: 채널 연동(OAuth), API 키, 어댑터 선택, 비용 한도.

| Phase | 범위 | 완료 기준 |

## 10. 비기능 요구사항

- **비용 추적**: 생성 호출마다 크레딧/원화 추정 비용 기록, 편당·테마당 집계. 편당 예산 한도 설정 가능 (기준: 편당 3,000~5,000원).
- **확장 게이트**: 테마의 최근 지표가 (승인률 ≥ 40% AND 채택률 ≥ 30%)를 충족하기 전에는 주간 생산 편수 확대 시 경고.
- **모델 교체 내성**: 어댑터 추가만으로 신규 모델 대응. 특정 벤더 SDK가 코어 로직에 새어 들어가면 안 됨.
- **게이트 불가침**: 어떤 자동화 설정으로도 GATE 2(프레임)·GATE 3(클립)을 건너뛸 수 없다.
- **언어**: UI·대본 한국어 기본, 생성 프롬프트는 영문.
- **로컬 우선**: 단일 사용자, 로컬 실행. 클라우드 배포는 범위 외.
