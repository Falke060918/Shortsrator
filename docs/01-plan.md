# Shortsrator 기획서

기반 문서: `docs/01_솔루션_개발명세.md` · `docs/02_제작방법론_소스정리.md` · `docs/03_테마명세_신비한건축사전.md` (사용자 작성 원본 명세 — 상세는 그쪽이 우선)

## 문제 정의 & 페인포인트
- 유튜브 숏츠를 꾸준히 생산하려면 주제 선정→대본→내레이션→이미지→영상→편집→업로드를 매편 반복해야 하며, 개인이 수작업으로는 편당 수 시간이 든다.
- AI 생성 도구는 많지만 채널의 고정 스타일(테마)을 유지하며 반복 생산하는 파이프라인이 없다 — 매번 프롬프트를 새로 짜고 품질이 흔들린다.
- 완전 자동화는 품질이 무너진다. 사람이 개입할 지점(컨펌 게이트)을 고정하고 나머지를 자동화하는 반자동 구조가 필요하다.

## 타겟 사용자
- 본인(1인) — 개인 유튜브 채널 운영 자동화용. 개인용 프로젝트로 시장조사는 생략(사용자 결정).

## 핵심 기능 (우선순위 순, MVP 표시)

MVP는 P1 코어 파이프라인 + 영상 생성 API 자동 연동(Higgsfield)이다. 컨펌 게이트 4개(시나리오/첫 프레임/클립/최종)는 스킵 불가.

## 로드맵
1. MVP: P1 코어 파이프라인(대본→TTS→프레임→I2V→조립, 게이트 4개) + Higgsfield API 자동 연동 → 파일럿 1편 완주. 우선순위: 품질보다 빠른 완주(사용자 결정).
2. P2: YouTube 업로드 연동 (REQ-UPLOAD-01)
3. P3: Theme Lab, 테마 버전 관리 고도화 (REQ-LAB-01)
4. P4: 개선 루프 — 승인률(≥40%)·채택률(≥30%) 지표 기반 테마 개선

## 비기능 요구사항
- 로컬 단독 실행(1인 사용, 서버 배포 없음). 데이터는 로컬 SQLite.
- API 키·인증 정보는 로컬 환경변수/설정 파일로만 관리, 저장소에 커밋 금지.
- 벤더 락 금지 — 모든 외부 모델 호출은 어댑터 레이어 경유.
- 편당 사람 개입 시간 목표 60분 이내(방법론 문서 기준).
- 스택 기본값: TS/Node + SQLite + ffmpeg (문서 권장안, 세부는 /architect에서 확정).
