# Shortsrator — 제작 방법론 소스 정리

> 원본: `shortsrator 소스.txt` (2026-08 기준). 솔루션의 파이프라인 설계 원리로 내장되는 지식 베이스.
> 이 문서는 "테마가 무엇이든 변하지 않는 공통 원칙"만 담는다. 테마별 규칙은 각 테마 명세 문서에 둔다.

---

## 1. 핵심 원칙

### 1-1. Text-to-Video가 아니라 Image-to-Video
- 텍스트로 바로 영상을 뽑으면 매번 구조·구도·물리가 바뀌고 크레딧만 태운다.
- 올바른 순서: **① 완벽한 첫 프레임 생성 → ② 그 이미지를 영상 모델에 입력 → ③ 프롬프트에는 움직임만 지정.**
- 입력 이미지가 구도·피사체·조명·스타일을 정의하므로, 영상 프롬프트는 거의 전적으로 motion만 설명한다 (Runway 공식 가이드).

### 1-2. 퀄리티를 결정하는 변수와 비중

| 변수 | 비중 | 내용 |
|---|---|---|
| 첫 프레임 품질 | 50% | 구도·조명·스타일이 여기서 확정됨 |
| 카메라가 정보를 전달 | 30% | 내레이션 문장과 카메라 이동이 동기화 |
| 채택률 관리 | 20% | 생성 8초 중 2초만 씀. 폐기 전제 |

- **프롬프트 엔지니어링은 4순위.** 마스터해야 할 기술 3개:
  1. 원하는 첫 프레임을 만드는 능력
  2. 그 프레임에 정확한 카메라 움직임을 주는 능력
  3. AI가 만든 5~8초 중 쓸 만한 2초만 골라 편집하는 능력

### 1-3. 카메라는 장식이 아니라 정보 전달 장치
- 내레이션 "비밀은 지하 20미터에 있었습니다" → 화면도 동시에 `ground → camera descending → underground → structure revealed`.
- 내레이션 문장 내용과 카메라 동선이 1:1로 동기화되어야 한다. 이 원칙 하나로 영상 느낌이 바뀐다.

## 2. 제작 순서 (오디오 우선 — 9단계)

```
1. 대본 (한국어, 초당 4~5음절 기준)
2. TTS 먼저 생성            ← 핵심
3. 오디오 파형 보고 컷 경계 확정 (실측 초)
4. 샷 리스트 = 내레이션 문장 단위로 분할
5. 각 샷의 첫 프레임 이미지 생성
6. 첫 프레임 육안 승인        (여기서 60% 반려)
7. Image-to-Video, 샷당 2~3회 생성
8. 좋은 구간 1.5~3초만 발췌
9. 편집: 자막 + 화살표 + SFX + BGM
```

**왜 TTS가 먼저인가**: 내레이션이 실측 2.4초면 그 컷은 2.4초짜리 카메라 동작이어야 한다. 영상을 먼저 만들면 오디오를 영상에 억지로 맞추게 되고, 그것이 "AI 숏츠 특유의 붕 뜨는 느낌"의 원인.

50초 숏츠 = 5초 × 10개가 아니다. 실제로는 `Shot01 2.1s / Shot02 2.8s / Shot03 1.6s / …`처럼 실측 기반 가변 길이. AI가 만든 8초를 전부 쓸 필요 없다 — 가장 좋은 순간만 발췌.

---

## 3. 자동화 가능/불가 경계

| 단계 | 자동화 | 방법 |
|---|---|---|
| 대본 생성 | 가능 | LLM + 고정 포맷 프롬프트 |
| 샷 분할 | 가능 | 내레이션 문장 → 샷 1:1 매핑 규칙 |
| 이미지 프롬프트 생성 | 가능 | 스타일 문자열 고정 + 피사체만 변수 |
| 영상 프롬프트 생성 | 가능 | 카메라 7종 중 선택 + 템플릿 |
| TTS | 가능 | API |
| 자막 | 가능 | 자동자막 |
| **첫 프레임 승인** | **불가** | 사람이 봐야 함 |
| **클립 구간 선별** | **불가** | 사람이 봐야 함 |
| **카메라 무빙 검수** | **불가** | 사람이 봐야 함 |

- 전체 자동화는 불가능. 잘하는 채널은 "자동화로 5편"이 아니라 **자동화된 앞단 + 고속 수동 선별**.
- **승인 지점 2개(첫 프레임 승인, 클립 선별)를 남겨두는 것이 자동화 설계의 전부.**
- 현실적 목표: 편당 작업시간 4시간 → **60분**. 0분은 안 된다.

## 4. 스타일 락 (채널 일관성)

채널 느낌은 이 두 가지로 결정된다.

1. **스타일 문자열 고정** — 모든 이미지 프롬프트 끝에 동일하게 붙인다. (테마별로 정의; 예시는 테마 명세 참조)
2. **Master Asset** — 주제 하나당 기준 이미지 4장을 먼저 만들고 재사용.
   - 예 (건축): 외부 전경 / 내부 / 단면도 / 구조 컷어웨이
   - Flow의 Ingredients-to-Video는 여러 레퍼런스 이미지로 캐릭터·오브젝트·스타일을 통제하도록 설계됨. 이걸 안 쓰면 컷마다 다른 피사체가 나온다.

## 5. 영상 프롬프트 공식

### 5-1. I2V 프롬프트는 짧아야 한다
첫 이미지가 이미 구도·재질·조명을 담고 있으므로 다시 설명하지 않는다. 프롬프트 구조:

```
CAMERA + CAMERA PATH + REVEAL + ENVIRONMENT MOTION + CONTINUITY
```

### 5-2. 기본 공식 (거의 모든 장면에 적용)

```
The camera [CAMERA MOVEMENT]
at [SPEED],
then [SECOND CAMERA MOVEMENT],
revealing [TARGET INFORMATION].

[OBJECT / ENVIRONMENT] moves [MOTION].

Continuous seamless cinematic shot.
```

### 5-3. 카메라 명령 개수 규칙
- 한 클립: 카메라 동작 **1~2개**
- 특별한 리빌 장면: **최대 3개** (A → B → C 순차 구조)
- drone/zoom/orbit/pan/tilt/crane/dolly/rack focus/360 spin을 한꺼번에 넣으면 망가진다.
- 단순한 프롬프트에서 시작해 motion 요소를 하나씩 추가 (Runway 권장).

### 5-4. 복합 카메라 예시 (A→B→C)

```
The camera begins with a wide aerial view.
It slowly descends toward the bridge while moving forward.
As it approaches the structure,
the camera accelerates and passes underneath the bridge.
It then tilts upward,
revealing the hidden support system from below.
Continuous seamless shot.
```

## 6. 카메라 무빙 7종 (이것만으로 대부분 해결)

| # | 무빙 | 용도 | 영문 프롬프트 |
|---|---|---|---|
| ① | Slow push-in | 궁금증 | `The camera slowly pushes toward the structure.` |
| ② | Dolly + tilt | 크기 강조 | `The camera dollies forward toward the structure while gradually tilting upward.` |
| ③ | Orbit | 구조 설명 | `The camera smoothly arcs clockwise around the structure, revealing its hidden backside.` |
| ④ | Fly-through | 내부 공개 | `The camera accelerates forward and smoothly flies through the opening into the interior structure.` |
| ⑤ | Descending drone | 스케일 | `The aerial camera slowly descends while moving toward the center of the structure.` |
| ⑥ | Macro → pull back | 정체 공개 | `The camera begins extremely close to the surface, then rapidly pulls backward, revealing the enormous structure.` |
| ⑦ | Follow path | 물·힘·흐름 추적 | `The camera follows the flowing water as it travels through the narrow channel and enters the underground system.` |

## 7. Start Frame + End Frame 기법

어려운 전환(내부 진입, 구조 변화)은 시작·끝 프레임 두 지점을 고정하고 그 사이를 생성시킨다.

예:
- START FRAME: 경기장 외부 / END FRAME: 경기장 지붕 내부 케이블 구조
- 프롬프트:
  ```
  The camera rapidly approaches the stadium roof,
  passes smoothly through the outer structure,
  and transitions into the interior cable system.
  Continuous forward camera movement.
  ```

## 8. 생성 방식 비율 (편당 구성)

| 비율 | 방식 | 용도 |
|---|---|---|
| 70% | Image → Video | 정확한 구도 + 카메라 이동 |
| 15% | Start Frame → End Frame | 내부 진입 / 구조 변화 / 전환 |
| 10% | Text → Video | 먼지, 폭풍, 바다, 도시 aerial 등 일관성이 중요하지 않은 B-roll |
| 5% | 편집 애니메이션 | 화살표 / X / 선 / 확대 / 그래프 / 자막 |

---

## 9. 편집 규칙

- **컷 길이 리듬**: 초반 3컷 1.5~2초 → 중반 2.5~3초 → 리빌 컷만 4초. 균등 분할하면 지루하다.
- **훅 3초**: 첫 컷은 반드시 "결과 이미지" 또는 "이상한 구조". 설명 컷을 먼저 두면 이탈.
- **화살표·수치·X 표시는 절대 AI로 생성하지 않는다.** 영상은 피사체 움직임·카메라·구조 변화만 생성하고, →/↓/X/원/라인/숫자는 편집 툴에서 오버레이. (편집 툴이 훨씬 정확)
- **SFX 밀도**: 컷 전환마다 트랜지션음 + 리빌 지점에 저음 임팩트. **무음 구간 0.5초 이상 금지.**
- **BGM**: 채널 통틀어 2~3곡만 로테이션 — 이것이 "이 채널 느낌"을 만든다.
- **자막**: 자동 자막 추출 후 가독성 높은 폰트/애니메이션.

| 역할 | 모델 | 근거 |

| 메인 I2V | Veo 3.1 (Flow) | 네이티브 9:16, 1080p/4K, Frames-to-Video, Ingredients(레퍼런스) |
| 정지 이미지 애니메이션 | Seedance 2 | I2V 아레나 1위(1196 Elo, 2026-08), @레퍼런스 12~50개 파일, video-reference |
| 복합 카메라 무빙 | Runway Gen-4.5 | 레퍼런스 이미지 + 카메라 컨트롤, 통제형 I2V 강자 |
| 멀티샷 시퀀스 | Kling 3.0 | 15초 1회 생성에 라벨링된 샷 최대 6개 |
| 초안/테스트 | Veo Fast/Lite | 여러 버전 저비용 테스트 |

**주의**
- **Sora 사용 금지**: 2026-04-26 웹·앱 종료, API도 2026-09-24 종료 예정. 낡은 가이드가 아직 추천 중.
- 12개월간 최상위 모델이 최소 3번 바뀌었다. **한 벤더에 워크플로 고정 = 벤더 락 금지. 파이프라인은 모델 교체 가능하게 설계.**
- 시작은 Flow 하나로 충분. Seedance/Runway는 Flow 결과가 막힐 때만.

**TTS/보이스**
- ElevenLabs: 다큐멘터리 성우 톤·감정 표현 최상급, 다국어.
- Typecast: 한국어 특화, 세밀한 억양 조절.
- 보이스 톤이 이 장르 분위기의 80%를 좌우한다 — 다큐/미스터리 계열 보이스 고정.

**비용 팩트**: 숏츠 1편(10~15컷) ≈ 3,000~5,000원 크레딧.

## 11. 측정 지표와 진단 규칙 (개선 루프의 심장)

편마다 두 수치를 기록한다:

| 지표 | 정의 | 임계값 | 진단 |
|---|---|---|---|
| **첫 프레임 승인률** | 생성 이미지 중 한 번에 통과한 비율 | < 40% | **이미지 프롬프트** 문제 → 스타일 문자열/피사체 기술 수정 |
| **클립 채택률** | 생성 클립 중 쓸 만한 비율 | < 30% | **카메라 프롬프트 과함** → 동작 개수 축소·단순화 |

**이 두 수치가 안정되기 전에 편수를 늘리면 크레딧만 태운다.** (편수 확대 게이트)

## 12. 첫 실행안 — 15초 5컷 파일럿 템플릿

60초를 먼저 만들지 않는다. 15초 5컷부터.

```
SHOT 1  3.0s  Wide establishing   → slow push-in
SHOT 2  2.0s  Detail              → macro → pull back
SHOT 3  3.0s  Fly-through         → 내부 진입
SHOT 4  3.0s  Cross-section       → Frames-to-Video (외부→단면)
SHOT 5  4.0s  Reveal              → orbit
```

15초가 되면 60초도 동일하다 — 샷이 늘어날 뿐.

## 13. 버려야 할 방식 (안티패턴)

```
ChatGPT 대본 → 12개 영문 프롬프트 → 각각 Text-to-Video → 편집 툴에서 합치기
```
인터넷에 가장 많이 도는 방법이고, 결과물에서 가장 쉽게 "AI 쇼츠 냄새"가 난다. 이 흐름은 솔루션에서 지원하지 않는다.

올바른 흐름:
```
대본 → Visual direction → First Frame → 프레임 직접 승인 → Image-to-Video
→ Camera choreography → 좋은 구간만 잘라 사용
```

## 14. 대본 구조 (LLM 생성 규칙)

- 한국어, **초당 4~5음절** 기준으로 길이 산정.
- 구조: **강렬한 훅 → 흥미로운 정보 제공 → 다음 영상을 기대하게 만드는 마무리.**
- 첫 3초가 생명 — 훅 문장이 첫 컷 비주얼(결과/이상한 구조)과 짝을 이뤄야 한다.
- 레퍼런스 분석 프롬프트 패턴: "이 대본의 구조를 분석해 → 동일한 텐션·구조를 유지하면서 주제만 X로 바꿔 60초 분량 한국어 대본 작성."
