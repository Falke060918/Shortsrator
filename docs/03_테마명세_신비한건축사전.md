# Shortsrator — 테마 명세: 신비한건축사전 스타일 (첫 테스트 테마)

> 레퍼런스: YouTube 채널 **신비한건축사전**. 솔루션의 첫 내장 테마 프리셋이자, 테마 정의 프레임워크의 견본.
> 이 문서 구조 자체가 "테마 하나를 정의할 때 채워야 하는 항목들"이므로, 새 테마(예: 역사 전투 탑뷰)도 같은 틀로 작성한다.

---

## 0. 테마 개요

| 항목 | 값 |
|---|---|
| 테마 이름 | 신비한 건축 (architecture-mystery) |
| 콘텐츠 정의 | 건축물의 숨겨진 구조·원리를 다큐 톤으로 "리빌"하는 세로 숏츠 |
| 포맷 | 9:16 세로, 파일럿 15초(5컷) → 안정화 후 45~60초(10~15컷) |
| 시청 감정 | 궁금증 → 스케일 압도 → 구조 리빌의 카타르시스 |
| 상태 | DRAFT (파일럿 검증 전) |

## 1. 주제 공식 (Topic Rules)

주제 유형 3종 — 모든 주제는 이 중 하나의 질문형으로 변환한다:

1. **왜 무너지지 않는가**: "로마의 판테온 돔은 왜 무너지지 않는가?"
2. **숨겨진 구조**: "이 다리 아래에는 아무도 모르는 구조가 있다"
3. **불가능해 보이는 건축**: "심해에 존재하는 미스터리 유적지"

초기 주제 큐 후보:
- 판테온 돔 (무보강 콘크리트 돔이 2000년 버티는 이유)
- 대형 현수교의 하부 지지 구조
- 댐 내부에서 수압이 분산되는 방식
- 경기장 지붕의 케이블 구조
- 지하 20미터의 고대 저수조
- 심해 미스터리 유적지 (B-roll 비중 높은 편)
- 초고층 빌딩의 튜닝 매스 댐퍼
- 고대 로마 수도교의 경사 설계

## 2. 대본 규칙 (Script Rules)

- 언어: 한국어. **초당 4~5음절**로 길이 산정.
- 구조: `강렬한 훅(1문장) → 흥미로운 정보 2~3단계 → 리빌(핵심 답) → 다음 영상 기대 마무리`.
- 훅 문장은 반드시 첫 컷 비주얼(결과 이미지/이상한 구조)과 짝을 이룬다. 설명으로 시작 금지.
- 문장 1개 = 샷 1개 (샷 분할 규칙과 직결되므로 문장을 짧게 쓴다).
- 톤: 다큐멘터리 내레이션. 감탄사·구어체 최소화, 단정형 종결.

훅 예시 패턴:
- "비밀은 지하 20미터에 있었습니다."
- "이 돔은 2000년째 무너지지 않고 있습니다."
- "아무도 이 다리의 아래를 본 적이 없습니다."

## 3. 고정 스타일 문자열 (Style Lock)

모든 이미지 프롬프트 끝에 동일하게 부착:

```
photorealistic architectural visualization,
cinematic documentary lighting,
physically accurate materials,
museum-quality reconstruction,
muted cool color grade,
high structural detail,
9:16 vertical
```

> 소스의 두 변형("soft dramatic lighting" 포함본)을 병합한 초안. 파일럿에서 승인률을 보고 v2에서 조정한다.

## 4. 마스터 애셋 스키마 (Master Asset Schema)

주제 하나당 본 생성 전에 기준 이미지 **4장**을 먼저 만들고, 이후 모든 첫 프레임의 레퍼런스로 재사용 (Flow Ingredients / API reference 입력):

| 역할 | 내용 | 예 (판테온) |
|---|---|---|
| EXTERIOR | 외부 전경 | Pantheon exterior |
| INTERIOR | 내부 | Pantheon interior |
| CROSS-SECTION | 단면도 | Pantheon dome cross-section |
| CUTAWAY | 구조 컷어웨이 | Pantheon structure cutaway |

이걸 안 쓰면 컷마다 다른 건물이 나온다.

## 5. 카메라 문법 (Camera Grammar) — 이 테마의 무빙-의미 매핑

| 무빙 | 이 테마에서의 용도 | 사용 빈도 |
|---|---|---|
| ① Slow push-in | 훅/궁금증 (오프닝) | 높음 |
| ② Dolly + tilt | 크기·스케일 강조 | 높음 |
| ③ Orbit | 구조 설명, 리빌 컷 | 높음 |
| ④ Fly-through | 내부 진입 | 높음 |
| ⑤ Descending drone | 스케일, "지하로" 전환 | 중간 |
| ⑥ Macro → pull back | 정체 공개 (디테일→전체) | 중간 |
| ⑦ Follow path | 물·하중·힘의 흐름 추적 | 중간 |

- 한 클립 카메라 동작 1~2개, 리빌 컷만 최대 3개 (A→B→C).
- **내레이션-카메라 동기화 필수**: "지하에 있다" → 하강 계열, "버틴다/분산된다" → follow path, "거대하다" → dolly+tilt 또는 descending drone.

### 이 테마의 대표 영상 프롬프트 예시

교량 하부 (첫 프레임: 거대한 교량을 아래에서 바라보는 장면):
```
The camera slowly dollies forward beneath the bridge,
then smoothly tilts upward while moving between the massive support columns.

As the camera approaches the center,
it arcs clockwise around one column,
revealing the hidden structural connections above.

Subtle wind moves through the environment.

Continuous seamless documentary shot.
```

Start+End Frame (경기장 — 외부에서 지붕 내부 케이블로):
```
START FRAME: 경기장 외부 / END FRAME: 지붕 내부 케이블 구조

The camera rapidly approaches the stadium roof,
passes smoothly through the outer structure,
and transitions into the interior cable system.
Continuous forward camera movement.
```

## 6. 샷 구성 규칙 (Shot Rules)

- 생성 방식 비율: **I2V 70% / Start+End 15% / T2V(B-roll) 10% / 편집 애니메이션 5%**
- 컷 길이 리듬: 초반 3컷 1.5~2초 → 중반 2.5~3초 → 리빌 컷만 4초 (실측 TTS 길이가 최종 결정)
- 생성 클립 8초 중 채택은 1.5~3초만. 샷당 2~3회 생성.

### 표준 파일럿 (15초 5컷) — 첫 검증에 사용

```
SHOT 1  3.0s  Wide establishing   → ① slow push-in       (훅 문장)
SHOT 2  2.0s  Detail              → ⑥ macro → pull back   (정체 암시)
SHOT 3  3.0s  Fly-through         → ④ 내부 진입           (정보)
SHOT 4  3.0s  Cross-section       → Start+End Frame (외부→단면) (정보)
SHOT 5  4.0s  Reveal              → ③ orbit               (리빌 + 마무리)
```

## 7. 보이스·오디오 규칙 (Voice & Audio)

- **보이스**: 다큐멘터리/미스터리 톤의 깊고 웅장한 남성 보이스로 고정. 1순위 ElevenLabs(감정 표현), 한국어 억양 이슈 시 Typecast. 보이스 톤이 이 장르 분위기의 80%를 좌우 — 채널 전체에서 절대 바꾸지 않는다.
- **BGM**: 한스 짐머풍 웅장/미스터리 오케스트라 **2~3곡만 로테이션** (채널 시그니처).
- **SFX**: 컷 전환마다 트랜지션음('우웅~', '쉬익-'), 구조 리빌 지점에 저음 임팩트. 무음 0.5초 이상 금지.

---

## 8. 편집·오버레이 규칙 (Edit Rules)

- 화살표(→↓), X 표시, 원, 라인, 수치, 그래프는 **AI 생성 금지** — 조립 후 편집 단계에서 오버레이 (CapCut 마감 모드 또는 ffmpeg 오버레이).
- 자막: 자동 자막 기반, 노란색 계열/애니메이션 폰트로 가독성 확보. 타이밍은 TTS 실측.
- 훅 3초 규칙: 첫 컷은 결과 이미지 또는 이상한 구조. 설명 컷 선행 금지.

## 9. 업로드 템플릿 (Upload Template)

- 제목: 훅 질문형 — 예: "판테온 돔이 2000년 무너지지 않는 이유", "이 다리 아래엔 비밀이 있다 #shorts"
- 설명: 1~2문장 요약 + 시리즈 안내 + 해시태그 (#건축 #구조 #미스터리 #shorts)
- 업로드 주기: 파일럿 검증 후 주 3편으로 시작 → 지표 안정 시 확대 (확장 게이트 적용)

## 11. 품질 게이트 & 개선 기준 (Metrics)

| 지표 | 목표 | 미달 시 조치 |
|---|---|---|
| 첫 프레임 승인률 | ≥ 40% | 스타일 문자열/피사체 기술 수정 (§3 개정 → 테마 v2) |
| 클립 채택률 | ≥ 30% | 카메라 프롬프트 단순화 — 동작 개수 축소 (§5 개정) |

- 파일럿(15초 5컷)을 2~3회 돌려 두 지표가 목표 이상으로 안정되면 → 테마 **FIXED**, 채널 바인딩, 60초 확대.
- 안정 전 편수 확대 금지 (크레딧 소모만 발생).
- 예상 비용: 편당 3,000~5,000원 크레딧.

## 12. 첫 파일럿 실행안 (권장)

- **주제**: "로마의 판테온 돔은 왜 무너지지 않는가?"
- 절차: 마스터 애셋 4장 생성 → 15초 5컷 파일럿을 파이프라인 전체(게이트 포함)로 1회 완주 → 승인률/채택률 기록 → §3·§5 조정 → 2차 파일럿.
- 이 완주 1회가 솔루션 P1(코어 파이프라인)의 완료 기준과 일치한다.
