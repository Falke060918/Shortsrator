# Status protocol — 작업 단위별 진행 단계 파일

위임한 단위(unit)가 지금 어느 단계에 있는지를 **파일 한 줄로** 남기는 규약이다.
세션 기억이나 터미널 화면이 아니라 이 파일이 사실이며, statusline 같은 읽는 쪽은 이 파일만 본다.

SYNC NOTE: 이 규약이 정하는 **한 줄 명령·경로·stage 토큰·source 토큰**의 사본이 아래에도 들어 있다. 여기를 고치면 아래도 같은 커밋에서 함께 고친다.
- `.claude/agents/implementer.md` — 한 줄 명령 + `probe`/`write`/`verify`/`done`/`fail` 전이 + `sub`/`child@<워크트리>` + land 수행 위임일 때만 병합 성공 뒤 `landed`
- `.claude/agents/reviewer.md` — 한 줄 명령 + `verify`/`done`/`fail`
- `.claude/agents/explorer.md` — 한 줄 명령 + `probe`/`done`
- `.claude/agents/orchestrator.md` — 단위 이름·노트 문구 전달 규칙, Orca는 자식 우선(`write`/`verify`는 자식이 쓴다) + 프록시의 시작 `probe`와 백스톱 마감
- `.claude/agents/planner.md` — 한 줄 명령 사본 없음. "planner는 status를 쓰지 않는다"만 적혀 있다
- `.claude/skills/land/SKILL.md` — 병합 성공 뒤 `landed`를 쓰는 한 줄
- `scripts/statusline.sh` — 읽는 쪽. 루트 고정(`_repo_root`가 fork 없이 git common dir와 같은 곳을 찾는다)·칸 나누기·stage 토큰·단계별 만료(진행 중 1시간·마감 60초)·source 라벨·워크트리 번호 배정·빈 노트 처리를 여기와 맞춘다

## 위치와 이름

- 경로: `<메인 저장소 루트>/.claude/perf/units/<unit>.status` — 단위 하나당 파일 하나. 파일명이 곧 단위 이름이다.
- **루트는 반드시 메인 저장소에 고정한다.** 상대 경로 `.claude/perf/units/`로 그냥 쓰면, 격리 워크트리
  안에서 도는 에이전트는 자기 워크트리 안에 파일을 만들고 메인 저장소에서 도는 읽는 쪽은 그것을 영영 못 본다.
  루트는 git의 common dir에서 뽑는다 — 어디서 실행하든(메인 체크아웃 최상위·하위 디렉터리·연결된 워크트리) 같은 곳을 가리킨다.

  ```bash
  root="$(git rev-parse --git-common-dir 2>/dev/null)"; root="${root%.git}"; root="${root%/}"; dir="${root:-.}/.claude/perf/units"
  ```

  `--git-common-dir`는 메인 최상위에서 `.git`, 메인 하위에서 `../.git`, 연결된 워크트리에서 메인 저장소의 절대 경로 `<repo>/.git`를 준다.
  뒤의 `.git`과 남는 슬래시를 떼면 각각 빈 문자열(→ `.`) · `..` · `<repo>`가 되어 전부 같은 메인 저장소 루트를 가리킨다.
  git 저장소가 아니면 빈 값이라 `.`로 떨어진다 — 그때는 현재 디렉터리에 쓰고 조용히 넘어간다.
- `<unit>`은 ASCII 소문자·숫자·하이픈만 쓴다(kebab-case: `status-protocol`, `readme-rewrite`).
- **슬래시가 들어간 이름은 그대로 쓰지 않는다.** 브랜치 이름에서 만들 때 `Falke060918/status-protocol` 같은
  소유자 접두사가 붙으면 경로에 없는 하위 디렉터리가 생겨 쓰기가 `No such file or directory`로 실패한다.
  소유자 접두사와 슬래시를 모두 떼고 **마지막 경로 조각만** 소문자 kebab-case로 쓴다(`${unit##*/}` → `status-protocol`).
- 이름은 **위임 프롬프트에 명시된 것을 그대로** 쓴다. 받은 쪽이 임의로 줄이거나 바꾸지 않는다 —
  이름이 어긋나면 같은 단위가 파일 두 개로 갈라져 읽는 쪽이 둘 다 놓친다.
- `.gitignore`는 **손대지 않는다.** `.claude/perf/`는 이미 무시 대상이고 그 디렉터리는 자기 자신도 무시한다
  (`scripts/perf-log.sh`가 `.claude/perf/.gitignore`에 `*`를 써 둔다). 새 무시 규칙을 추가할 이유가 없다.

## 형식

정확히 **한 줄**, 파이프(`|`)로 나눈 **다섯 칸**의 평문이다. JSON이 아니다.

```
<stage>|<unit>|<epoch-seconds>|<한 줄 노트>|<source>
```

| 칸 | 내용 |
| --- | --- |
| `<stage>` | 아래 여섯 토큰 중 하나. |
| `<unit>` | 단위 이름. 파일명(`<unit>.status`)과 반드시 같다. |
| `<epoch-seconds>` | 쓴 시각의 유닉스 초. `date +%s`. |
| `<한 줄 노트>` | **무슨 작업인지**를 적는다. 단계를 반복하지 않는다 — 아래 "노트 칸" 참조. |
| `<source>` | 누가 썼는지. `<kind>` 또는 `<kind>@<워크트리 이름>`. kind는 `main`/`sub`/`child` 셋뿐이다. |

- 노트에 **파이프 문자(`|`)와 줄바꿈을 넣지 않는다** — 읽는 쪽이 칸을 잘못 자른다.
  파이프가 하나만 섞여도 노트 꼬리가 source 칸으로 밀려 들어가고(라벨이 사라진다),
  source까지 붙어 있으면 여섯 칸짜리 줄이 되어 읽는 쪽이 그 단위를 통째로 버린다(에러도 안 난다).
  그래서 아래 한 줄 명령은 노트를 그대로 쓰지 않고 `${note//|/ }`로 파이프를 공백으로 바꿔 넣는다 — 규칙에만 기대지 않는다.
- **노트가 비어도(`write|unit|1755583380||sub`) 그 줄은 버려지지 않는다** — 읽는 쪽이 메모 칸만 빼고 렌더한다.
  빈 노트는 규약 위반이 아니라 권장 위반일 뿐이니, 쓸 말이 마땅치 않다고 줄 자체를 안 쓰는 것보다는 비워서라도 쓰는 편이 낫다.
  뒤쪽 칸이 통째로 없는 줄(`write|unit|1755583380|노트`, `write|unit|1755583380`)도 같게 취급한다.
- **읽는 쪽은 앞에서부터 칸을 세고 짧은 꼬리를 관용한다.** 정확한 칸 수 검사는 금지다 —
  source 칸이 없는 **네 칸짜리 옛 줄도 계속 정상 렌더된다**(하위 호환 필수). 출처 라벨 자리만 빈다.
- 파일은 항상 한 줄이다. 여러 줄이 되면 읽는 쪽은 첫 줄만 유효한 것으로 본다.
- 읽는 쪽은 bash 내장으로만 파싱한다(`IFS='|' read -r -a`, 길이는 `read -n`으로 경계). 이 머신에 **jq가 없다** — 구조화 포맷으로 바꾸지 않는다.

## source 칸과 출처 라벨

| kind | 뜻 | 화면 라벨 |
| --- | --- | --- |
| `main` | 메인 세션이 직접 쓴 줄 | `[M]` |
| `sub` | 내부 서브에이전트. 워크트리 소속이 없으면 `sub` | `[S]` |
| `sub@<워크트리 이름>` | 그 워크트리를 몰고 있는 내부 서브에이전트(Orca 통합 프록시) | `[S/W1]` |
| `child@<워크트리 이름>` | 그 워크트리 **안에서** 도는 자식 에이전트 본인 | `[W1]` |

- **새 kind를 만들지 않는다.** 셋이 전부이고, 모르는 kind는 라벨 없이(옛 줄과 같게) 렌더된다.
- source 칸에는 `|`·공백·줄바꿈을 넣지 않는다. 라벨은 ASCII만 쓴다 — 고정폭 정렬 칸이라
  East-Asian Ambiguous 문자가 섞이면 터미널마다 칸이 어긋난다. 라벨은 최대 8칸이다.
- **워크트리 번호는 쓰는 쪽이 정하지 않는다.** 쓰는 쪽은 워크트리 **이름**만 남기고,
  읽는 쪽이 그 이름들을 **알파벳순으로 정렬해 1번부터** 배정한다. 그래서 같은 워크트리에 붙은
  프록시(`sub@a`)와 자식(`child@a`)이 **반드시 같은 번호**를 받고, 단위가 늘고 줄어도 번호가 흔들리지 않는다.
- 자식이 자기 워크트리 이름을 얻는 법: `git rev-parse --show-toplevel`의 마지막 경로 조각
  (또는 브랜치 이름의 마지막 경로 조각). 단위 이름과 같은 규칙으로 소문자 kebab-case다.

## 노트 칸

- **노트는 "무슨 작업인지"를 적는다. 단계를 반복하지 않는다.** 왼쪽 단계 칸이 이미 단계를 보여주므로
  거기에 단계를 또 적으면 화면에서 정작 무슨 일이 도는지가 사라진다.
- 좋은 예: `import 스킬 개선`, `상태줄 대시보드 개선`, `template-update 주석 정리`
- 나쁜 예: `검증 중`, `작업완료`, `자식 생성`, `probe`, `커밋함`
- 자유 문구지만 40자 내외로 짧게. **비우지 않는 것을 원칙으로 한다.**
- **한 단위 안에서 노트는 대체로 그대로 유지한다** — 단계가 바뀌어도 같은 문구를 다시 쓰는 것이 정상이다.
  세부를 갈아 끼워도 되지만 여전히 '무슨 작업'이어야 한다.
- 예외는 `fail`뿐이다 — 그때는 **무엇에 막혔는지** 한 줄로 적는다.

## stage 토큰

| stage | 뜻 |
| --- | --- |
| `probe` | 파악중 — 범위·대상 파일을 확인하는 중 |
| `write` | 작성중 — 실제로 파일을 고치는 중 |
| `verify` | 검증중 — 빌드·테스트·리뷰 대기 중 |
| `done` | 완료 |
| `landed` | 반영 — 결과가 메인 저장소에 병합됨. `done` 다음 단계다 |
| `fail` | 실패 — 무엇에 막혔는지 노트에 한 줄 |

정상 흐름은 `probe → write → verify → done → landed`이고, 실패로 끝나면 마지막 줄이 `fail`이다.
`landed`는 단위 담당이 아니라 **land(병합)를 수행하는 쪽**이 쓴다 — 병합은 단위가 끝난 뒤 메인 저장소에서 일어나므로 src는 `sub` 또는 `main`이다.
여섯 토큰이 전부다. 새 토큰을 만들지 않는다.

## 쓰기 규칙

- 전이할 때마다 **파일 전체를 덮어쓴다.** append가 아니다 — 파일에는 항상 현재 한 줄만 있다.
- 한 줄 명령(루트 고정 → 이름 정리 → 디렉터리 생성 → 리다이렉트). `write`와 노트와 `src`만 상황에 맞게 갈아 끼운다:

  ```bash
  root="$(git rev-parse --git-common-dir 2>/dev/null)"; root="${root%.git}"; root="${root%/}"; dir="${root:-.}/.claude/perf/units"; unit=my-unit; unit="${unit##*/}"; note='상태줄 대시보드 개선'; src=sub; { mkdir -p "$dir" && printf '%s|%s|%s|%s|%s\n' write "$unit" "$(date +%s)" "${note//|/ }" "${src//[|[:space:]]/}" > "$dir/$unit.status"; } 2>/dev/null || true
  ```

  마지막 `2>/dev/null || true`는 장식이 아니다 — best-effort를 **말이 아니라 구조로** 보장한다.
  이게 없으면 쓰기 실패가 종료 코드 1과 stderr로 새어 나와 본 작업이 실패한 것처럼 보인다.
  `${src//[|[:space:]]/}`도 같은 이유다 — source에 파이프나 공백이 섞이면 칸이 어긋난다.
- 담당은 아래로 갈린다. **한 단위에 두 주체가 겹쳐 쓰지 않는 것이 원칙이고, 예외는 둘뿐이다 — Orca 프록시의 백스톱, 그리고 단위가 끝난 뒤 `landed`를 찍는 land 수행자.**
  - implementer: `probe` → `write` → `verify` → `done` 또는 `fail`. src는 워크트리 안이면 `child@<워크트리 이름>`, 메인 저장소면 `sub`
  - reviewer: `verify` → `done` 또는 `fail`. src 규칙은 implementer와 같다
  - explorer: 시작에 `probe`, 종료에 `done`. src 규칙은 implementer와 같다
  - 메인 세션이 직접 쓸 때: src는 `main`
  - land 수행자(`/land`를 도는 implementer 또는 메인 세션): 그 단위의 브랜치가 **실제로 병합된 뒤** `landed`.
    단위 담당 자식이 쓰는 것이 아니다 — 병합은 워크트리가 정리된 뒤 메인 저장소에서 일어나므로 src는 `sub`(또는 메인 세션이면 `main`)다.
    노트는 그 단위가 쓰던 문구를 그대로 재사용한다
  - Orca 통합 프록시: **백스톱이다.** worktree create 직후 `probe`(src `sub@<워크트리 이름>`)를 쓰고,
    끝에서는 상태 파일을 **읽어본 뒤** 자식이 이미 `done`/`fail`을 썼으면 손대지 않는다.
    자식이 거기까지 못 갔을 때만(죽었거나 멈췄을 때) 프록시가 `done`(커밋 성공) 또는 `fail`로 마감한다.
  - **자식 우선 원칙**: 워크트리 안 자식이 자기 단계를 직접 쓴다(`child@<워크트리 이름>`).
    프록시가 `verify`까지만 쓰고 끝나면 다 끝난 작업이 화면에 영영 '검증'으로 남는다 — 마감은 자식이 하고, 프록시는 자식이 실패했을 때만 대신 찍는다.
  - planner: **쓰지 않는다** — 셸 도구가 없어 쓸 수단 자체가 없다. planner 단위는 상태 파일이 아예 생기지 않아 대시보드에 줄이 뜨지 않는 것이 정상이다.
- 단위 이름을 위임 프롬프트에서 받지 못했으면 브랜치 이름의 **마지막 경로 조각**에서 만들고(위 "위치와 이름" 참조),
  그것도 없으면 **조용히 건너뛴다.**
- **best-effort다.** 쓰기가 실패해도 무시하고 본 작업을 계속한다. status 때문에 작업이 멈추거나 실패하거나
  재시도 루프에 빠지지 않는다. 실패를 에러로 보고하지도 않는다.

## 읽는 쪽

- 파일이 **없으면 그 단위는 화면에 아예 뜨지 않는다.** 없는 것은 실패가 아니다 — 아직 위임되지 않았거나 status를 쓰지 않는 경량 위임일 뿐이다. 읽는 쪽은 "미시작" 같은 라벨을 따로 찍지 않는다.
- **지난 세션의 낡은 파일은 그대로 남아도 무해하다** — 읽는 쪽이 만료된 줄을 무시한다. 따로 지우지 않아도 된다.
- **진행 중 단계(`probe`/`write`/`verify`) 줄은 마지막 갱신에서 1시간(3600초)이 지나면 화면에서 빠진다.** 그만큼 갱신이 멈춘
  단위는 진행 중인 일이 아니라 버려진 실행이다.
- **마감된 단계(`done`/`landed`/`fail`) 줄은 60초가 지나면 화면에서 빠진다.** 끝난 단위는 더 볼 것이 없는데 화면에 계속 남아
  진행 중인 줄을 밀어냈다.
- 두 만료 모두 **파일을 지우는 것이 아니라 렌더에서만 빼는 것**이고, 쓰는 쪽은 이 규칙 때문에 달라지지 않는다 — 따로 정리 명령을 두지 않는다.
- 형식이 깨진 줄을 만나도 읽는 쪽은 죽지 않고 그 단위만 건너뛴다. 상태 표시는 부가 정보이지 차단 조건이 아니다.
- 읽는 쪽도 **쓰는 쪽과 같은 메인 저장소 루트**를 찾아야 한다. 한쪽만 어긋나면 파일은 잘 쓰이는데 화면에는 아무것도 안 뜬다.
  `scripts/statusline.sh`는 세션 JSON의 `workspace.project_dir`에서 출발해 위로 `.git`을 찾아 올라가고(연결된 워크트리의
  `gitdir: <메인>/.git/worktrees/<이름>`이면 그 꼬리를 떼어 메인으로 되돌린다), 못 찾으면 그 자리를 그대로 쓴다 —
  결과는 위의 `--git-common-dir` 한 줄과 같은 곳이고, 상태줄 예산을 지키려고 프로세스는 하나도 띄우지 않는다.

## 예시

`<메인 저장소 루트>/.claude/perf/units/status-protocol.status` — 브랜치가 `Falke060918/status-protocol`이고
격리 워크트리 안에서 돌더라도 파일은 저 한 곳에 생긴다.

```
verify|status-protocol|1755583380|상태 규약 문서 정리|child@status-protocol
```

그 워크트리를 몰고 있는 프록시가 남긴 줄은 같은 번호를 받는다:

```
probe|status-protocol|1755583200|상태 규약 문서 정리|sub@status-protocol
```

화면(라벨 자리는 고정폭이고, source가 없는 옛 줄은 비워 둔다):

```
◑ [S/W1] status-board-fix   작성  12s  상태줄 대시보드 개선
✓ [S/W2] orca-recheck       완료  41s  orca 규약 버전 갱신
◑ [S]    readme-fix         작성   8s  README 문구 정리
◆ [S]    status-protocol    반영   6s  상태 규약 문서 정리
```
